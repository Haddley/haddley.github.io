**Summary.** Retrieval-augmented generation (RAG) improves the accuracy and specificity of large language model responses by providing relevant context from a knowledge base at runtime. This approach ensures that the model relies on retrieved data rather than its own internal memory to generate answers and citations.

## The idea
- RAG provides context by finding relevant text before the model generates an answer.
- Retrieval ensures citations are grounded in data rather than hallucinated by the model.
- Embedding models convert text into numbers to find passages, while separate models write the final response.
- Strict rules and curated document sets prevent the model from providing information from outside the provided context.
- Context injection is more efficient than including an entire knowledge base in every prompt.

## Claims
- RAG provides context by finding relevant text before the model generates an answer.
  > "Retrieval-Augmented Generation, RAG for short, is the pattern behind most of the useful AI applications being built right now: instead of asking a language model to answer purely from what it happened to be trained on, you find the specific, real, relevant text first, hand that to the model as context, and ask it to answer from that." — rag1
- The system ensures citations are accurate because the metadata is pulled from the database rather than generated by the LLM.
  > "The detail I think matters most here: citation *metadata* — case name, medium-neutral citation, page number — is read straight off the retrieved database rows, never generated by the model." — agenticaiforprofessionals2
- The embedding model is only used to find passages, while a separate model writes the final answer.
  > "The agent uses a separate model to write the answer from the passages that the search returns." — azurefoundryagent
- The system prevents hallucinated citations by reading metadata directly from the database.
  > "The citation metadata — case name, page number — is read directly off the retrieved database row, never generated by the model, so *which* excerpt gets cited is the LLM's call, but the citation itself can't be hallucinated." — agenticaiforprofessionals3
- The system uses a curated, scoped document set rather than the open web.
  > "That constraint turned out to be the right one to build around, not a limitation to route past: a curated, scoped document set someone actually put together by hand, then a single RAG-grounded Q&A skill run on top of it." — agenticaiforprofessionals1
- The vague agent provided information from outside the documents while the strict agent did not.
  > "The difference showed up on questions the documents do not cover: the vague agent answered 3 of 6 of them with legal information the documents do not directly cover, and the strict agent answered none of them that way." — azurefoundryagent6
- Context injection provides the model with relevant information from a knowledge base.
  > "Context injection is a technique that involves providing GPT-4 with additional relevant information from your knowledge base alongside the user’s query." — contextinjection
- The system ensures that prompts are written more efficiently.
  > "This technique has two specific benefits: (1) prompts are always more efficiently written, and (2) your data are always up to date." — contextinjection

## Where the posts differ
- The system moved from a vague approach where the model used internal memory to a strict approach where the model only uses the knowledge base.
  > "It answered 5 of the 6 outside questions confidently from memory, with figures such as a licence renewal fee, Wisconsin speed limits and a stop sign fine." — azurefoundryagent6
  > "The difference showed up on questions the documents do not cover: the vague agent answered 3 of 6 of them with legal information the documents do not directly cover, and the strict agent answered none of them that way." — azurefoundryagent6

## What I concluded
Retrieval-augmented generation is a critical architecture for building reliable applications because it grounds the model in specific, verifiable data. By separating the retrieval of facts from the generation of text, developers can significantly reduce hallucinations and improve accuracy.
