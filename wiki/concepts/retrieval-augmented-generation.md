**Summary.** Retrieval-augmented generation (RAG) improves the accuracy and specificity of large language model responses by providing relevant context from a knowledge base at runtime. This approach ensures that the model relies on retrieved data rather than its own internal memory to generate answers.

## The idea
- RAG provides context by finding relevant text before the model generates an answer.
- Retrieval ensures citations are grounded in data rather than hallucinated by the model.
- Embedding models convert text into numbers to find passages, while separate models generate the final response.
- Strict rules and curated document sets prevent the model from providing information from outside the provided context.
- Context injection is more efficient than including an entire knowledge base in every prompt.

## Claims
- RAG provides context by finding relevant text before the model generates an answer.
  > "Retrieval-Augmented Generation, RAG for short, is the pattern behind most of the useful AI applications being built right now: instead of asking a language model to answer purely from what it happened to be trained on, you find the specific, real, relevant text first, hand that to the model as context, and ask it to answer from that." — rag1
- The system ensures citations are accurate because the metadata is pulled from the database rather than generated by the LLM.
  > "The detail I think matters most here: citation *metadata* — case name, medium-neutral citation, page number — is read straight off the retrieved database rows, never generated by the model." — agenticaiforprofessionals2
- The system prevents hallucinated citations by reading metadata directly from the database.
  > "The citation metadata — case name, page number — is read directly off the retrieved database row, never generated by the model, so *which* excerpt gets cited is the LLM's call, but the citation itself can't be hallucinated." — agenticaiforprofessionals3
- The embedding model is only used to find passages, while a separate model writes the final answer.
  > "The agent uses a separate model to write the answer from the passages that the search returns." — azuresearchvector
- The strict agent correctly used the knowledge base and provided clickable sources.
  > "*I asked about DWI while asleep in a parked car, and the strict agent answered with the section name and two clickable references into the search index*" — azurefoundryagent6
- The system is restricted to performing tasks within that specific catalog and using a curated, scoped document set.
  > "It is restricted to only performing tasks inside that catalog." — agenticaiforprofessionals1
- Context injection improves the accuracy and specificity of the model.
  > "This helps guide the model’s response and enhances its accuracy, relevance, and specificity." — contextinjection
- The system ensures that prompts are written more efficiently.
  > "This technique has two specific benefits: (1) prompts are always more efficiently written, and (2) your data are always up to date." — contextinjection

## What I concluded
Retrieval-augmented generation is a critical architecture for building reliable systems because it grounds model outputs in specific, verifiable data. By separating the retrieval of facts from the generation of text, developers can significantly reduce hallucinations and improve accuracy.
