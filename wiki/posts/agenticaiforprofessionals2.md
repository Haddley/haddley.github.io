**Summary.** I built the core RAG infrastructure for a legal research assistant using a local-first architecture. The system provides a provider-agnostic layer that ensures citations are grounded in retrieved data rather than hallucinated by the model.

## What I did
- Built a local RAG system on a 32GB M4 MacBook Air using Docker and Ollama.
- Implemented a provider-agnostic LLM layer to allow easy switching between local and cloud models.
- Developed a page-safe chunking system to ensure accurate legal citations.
- Established a core RAG skill that retrieves and filters chunks based on cosine distance.
- Validated the data layer, LLM orchestration, and core RAG logic.

## Claims
- The system runs entirely locally on a MacBook Air without requiring cloud APIs.
  > "This post is the actual build: Phases 1 through 3 of that plan, all of it running locally on my 32GB M4 MacBook Air through Docker Compose, with Ollama serving both the chat model and the embeddings — no cloud API required to get a working system end to end."
- The embedding dimension must remain constant to match the specific model used during ingestion.
  > "The `EMBEDDING_DIM` constant matters more than it looks: it's fixed at table-creation time, and it has to match whichever model actually generated the vectors."
- The system uses a direct pypdf implementation instead of a LangChain wrapper.
  > "It's the same `pypdf` library under the hood as my earlier LangChain RAG project — there I went through LangChain's `PyPDFLoader` wrapper and let `load_and_split()` handle it; here I use `pypdf.PdfReader` directly."
- The architecture allows switching to a cloud provider via a single environment variable.
  > "Neither needs an API key, a network connection past the first `ollama pull`, or a cent of cloud spend — which is exactly the point of building this layer as swappable rather than hard-coding a single provider: the same code that runs free on my own machine today can point at Anthropic's API with one environment variable change once this is worth paying for, without touching a line of the RAG logic itself."
- The system ensures citations are accurate because the metadata is pulled from the database rather than generated by the LLM.
  > "The detail I think matters most here: citation *metadata* — case name, medium-neutral citation, page number — is read straight off the retrieved database rows, never generated by the model."
- The current build does not yet include the frontend interface or the MCP server.
  > "What's still checkbox-unticked in the build plan is the part a screenshot would actually show: Phase 4's React/TypeScript upload-and-chat interface, and Phase 5's MCP server exposing this same skill over the Model Context Protocol — Claude Code is the client I'll reach for first, but any MCP client can call it once it's standing."

## Outcome
I built a functional RAG core that provides accurate, verifiable citations for legal research. The system is designed to be provider-agnostic, allowing for easy scaling from local models to cloud APIs.
