This series is a guide for developers new to Business Central. I have been developing for Business Central for years, and many of the posts on this blog show that work, but I am following the labs for the MB-820 certification from the beginning and writing down what happens as it happens, mistakes included. I always learn something when I try to teach it.

## What the exam measures

Exam MB-820 is Microsoft Dynamics 365 Business Central Developer. The [study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/mb-820#skills-at-a-glance) says the person who passes it designs, develops, tests and maintains solutions based on Business Central, extends it with apps, integrates it with other applications such as the Microsoft Power Platform, and troubleshoots and debugs it. The skills at a glance, in the version that applies from 10 June 2025, are:

| Skill area | Weight |
|---|---|
| Describe Business Central | 10-15% |
| Install, develop, and deploy for Business Central | 10-15% |
| Develop by using AL objects | 35-40% |
| Develop by using AL | 15-20% |
| Work with development tools | 10-15% |
| Integrate Business Central with other applications | 10-15% |

:::no-dumb-questions
**Q: What is the difference between MB-820 and the Business Central Developer Associate certification?**

A: MB-820 is the exam. [Microsoft Certified: Dynamics 365 Business Central Developer Associate](https://learn.microsoft.com/en-us/credentials/certifications/d365-business-central-developer-associate/) is the credential I earn by passing it. The certification page lists MB-820 as its exam, and the exam is the only thing I have to pass. The page also links to the practice assessment, the exam sandbox and the study guide. The exam costs $165 USD in the United States, and the price depends on the country or region where it is proctored. It lasts 100 minutes and is proctored. The certification renews every 12 months, and the renewal is a free online assessment on Microsoft Learn.

**Q: What about the Functional Consultant Associate certification?**

A: [Microsoft Certified: Dynamics 365 Business Central Functional Consultant Associate](https://learn.microsoft.com/en-us/credentials/certifications/d365-business-central-functional-consultant-associate/) is the sibling certification, earned by passing Exam MB-800. It is for people who implement and configure Business Central rather than extend it with code: setting up the core application, financials, sales and purchasing, inventory and fixed assets, role centers, and Copilot capabilities. MB-820 is for developers who write AL. The [MB-800 study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/mb-800) groups its skills into setting up Business Central, configuring financials, configuring sales and purchasing, and performing Business Central operations. None of them asks me to write AL. The two exams are both 100 minutes, proctored, and renewed every 12 months, but they assess different skills, so I focus on MB-820.

**Q: Which account should I use to register?**

A: Microsoft strongly recommends a personal Microsoft account. If I register with an organizational (work or school) account, my exam records are lost, and cannot be recovered, when I leave that organization. The certification page links to [Schedule through Pearson VUE](https://learn.microsoft.com/en-us/credentials/certifications/schedule-through-pearson-vue?examUid=exam.MB-820&examUrl=https://learn.microsoft.com/credentials/certifications), which opens the registration for MB-820.
:::

The largest block, AL objects, covers tables, pages, reports, XMLports, codeunits, permission sets and queries. Because a series of posts has to start somewhere, I follow the order of Microsoft's labs. I use the study guide to find the skills the labs do not cover, and I link to posts on this blog where I have already covered a topic.

## Where this part fits

This part sits in **Install, develop, and deploy for Business Central**. The study guide lists these skills under it, and I practise each one here:

- Install and configure the development environment.
- Manage the configuration files of an AL extension (`app.json` and `launch.json`).
- Create an extension in Visual Studio Code and deploy it.

The Microsoft apps that the symbols come from also touch a skill in the first area: differentiating the base app and the system app.

This first part sets up the development environment: VS Code on my Mac, the AL extension, and a Business Central online sandbox. I finish by publishing an app that shows a message when the Customer List opens.

:::brain-power Before you read on
VS Code on my Mac has never seen Business Central. When I write `pageextension 50100 CustomerListExt extends "Customer List"`, how does the editor know what a "Customer List" page is, or what fields it has?
:::

## Create the project

I chose **View | Command Palette...** (Shift+Command+P) to open the Command Palette.

![](assets/images/mb820-1/view-command-palette.png)
*I chose View | Command Palette...*

Then I ran **AL: Go!**

![](assets/images/mb820-1/al-go-command.png)
*I ran AL: Go!*

It asked for a path to a new empty folder. I used `part1-hello` inside a `mb820` folder, so each part of the series gets its own project.

![](assets/images/mb820-1/new-project-folder.png)
*I chose a new empty folder for the project*

Next it asked for the target platform. I chose the newest, 18.0, which is Business Central 2026 release wave 2.

![](assets/images/mb820-1/target-platform.png)
*I chose platform 18.0, Business Central 2026 release wave 2*

Then it asked which server to use: my own server or the Microsoft cloud sandbox. I use an online sandbox, so I chose the Microsoft cloud sandbox. I explain why in the box below, and in [Business Central Development Environment](/posts/devenv/) I ran the container-based alternative on Docker for Windows.

![](assets/images/mb820-1/choose-the-server.png)
*I chose the Microsoft cloud sandbox*

:::no-dumb-questions
**Q: Why a cloud sandbox and not a Docker container?**

A: I work on a Mac. The container route in [the earlier post](/posts/devenv/) needs Windows. A sandbox environment is created in the Business Central admin center, which I covered in [Business Central Admin Center](/posts/businesscentraladmincenter/), and VS Code on any machine can publish to it.

**Q: Does the sandbox need a particular name?**

A: No. Any sandbox environment works. What matters is that `launch.json` holds its exact name.
:::

## The generated code

AL: Go! created `app.json`, `.vscode/launch.json` and `HelloWorld.al`. I changed the message in `HelloWorld.al` so I could recognise it later:

```al
namespace DefaultPublisher.part1hello;

using Microsoft.Sales.Customer;

pageextension 50100 CustomerListExt extends "Customer List"
{
    trigger OnOpenPage();
    begin
        Message('App published: Hello world - MB820');
    end;
}
```

![](assets/images/mb820-1/helloworld-al.png)
*I changed the message in HelloWorld.al*

A page extension adds to an existing page without changing Microsoft's code. The `OnOpenPage` trigger runs each time someone opens the Customer List.

## The first download of symbols failed

The editor showed red errors in `app.json` and `HelloWorld.al`. It had no idea what a "Customer List" was, because the Microsoft apps it extends were missing. They arrive as **symbols**, so I ran **AL: Download symbols**.

![](assets/images/mb820-1/download-symbols-command.png)
*I ran AL: Download symbols from the Command Palette*

It failed:

![](assets/images/mb820-1/download-symbols-error.png)
*"Please provide server settings in the launch.json file", and in the Output panel, "No server has been chosen"*

:::watch-it The environment name is not always "sandbox"
I assumed my sandbox would be called "sandbox". It is called **MB-820**. Symbols come from a URL that contains the environment name, so a wrong name means no symbols, and with no symbols nothing in the project compiles.
:::

## The fix: the right environment name

I opened `.vscode/launch.json` and set `environmentName` to the exact name of my sandbox, `MB-820`. Business Central shows the name at the top of the page: `Environment: MB-820`.

![](assets/images/mb820-1/launch-json-environment-name.png)
*I set environmentName to MB-820*

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Microsoft cloud sandbox",
            "request": "launch",
            "type": "al",
            "environmentType": "Sandbox",
            "environmentName": "MB-820",
            "startupObjectId": 22,
            "startupObjectType": "Page",
            "breakOnError": "All",
            "launchBrowser": true,
            "enableLongRunningSqlStatements": true,
            "enableSqlInformationDebugger": true
        }
    ]
}
```

`startupObjectId` 22 is the Customer List page. That is the page the browser opens after the app is published.

I ran **AL: Download symbols** again. This time the Output panel listed the requests going to `api.businesscentral.dynamics.com/v2.0/MB-820/dev/packages`, one for each of System Application, Business Foundation and Base Application, all version 29.0.0.0. Then I saw "Symbols have been downloaded." The Problems count dropped to 0 errors and 0 warnings.

![](assets/images/mb820-1/symbols-downloaded.png)
*Symbols downloaded, and the errors disappeared*

:::under-the-hood What symbols are
Symbols are the compiled description of an app: its tables, fields, pages and codeunits, without the source code. The AL compiler reads them from the `.alpackages` folder in my project. My app can extend the Customer List because the Base Application symbols describe it. The dependencies in `app.json` decide which symbols the compiler needs.
:::

## Publish and run

I chose **Run Without Debugging** from the Run menu. VS Code compiled the app, published it to the MB-820 sandbox, and opened a browser. I signed in with my Entra account.

![](assets/images/mb820-1/run-without-debugging.png)
*I chose Run Without Debugging*

The Customer List opened in CRONUS USA, Inc. in the MB-820 environment, and my message appeared.

![](assets/images/mb820-1/hello-world-message.png)
*App published: Hello world - MB820*

:::bullet-points Recap
- The AL Language extension is the only extension I needed to start.
- **AL: Go!** creates `app.json`, `launch.json` and a sample `HelloWorld.al`.
- **Download symbols** fills `.alpackages` with the Microsoft apps my code extends.
- In `launch.json`, `environmentName` must be the exact name of my sandbox, here `MB-820`.
- **Run Without Debugging** compiles, publishes and opens the page in `startupObjectId`.
:::

:::pencil Sharpen your pencil
Change `startupObjectId` in `launch.json` so the browser opens a different page after publishing. Which page would you open, and which ID would you use?

:::answer
I could use 21 for the Customer Card, or 30 for the Item Card. The ID is the object ID of any page in the Base Application.
:::
:::
